## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside buttons/menu items (`gap-1`) |
| sm | 8px | Compact Header gaps (`gap-2`), error-banner icon gap |
| md | 16px | LoginScreen/form field stack (`space-y-4`), modal body padding baseline |
| lg | 24px | LoginScreen brand block (`mb-8` = 32px uses xl); modal header/body 16–24px already on Modal |
| xl | 32px | LoginScreen brand `mb-8`; EmptyState padding (existing, do not restyle) |
| 2xl | 48px | Not used in new Phase 1 chrome |
| 3xl | 64px | Not used in new Phase 1 chrome |

Exceptions:

- **Header density (locked existing):** user chip `px-2`/`px-2.5` (8px/10px), `py-1` (4px), `gap-1.5` (6px). New account menu panel must match this chip: `rounded-lg`, `border-zinc-700`, `bg-zinc-900`, item padding `px-3 py-2` (12px / 8px). Do not “fix” Header to a looser scale.
- **Touch targets:** account-menu items and logout row `min-h-[32px]` on `md+` (match Header `Button` `sm`); `min-h-[44px]` below `md`. LoginScreen primary already uses Button `md` (`min-h-[38px]`); keep that — do not switch Entrar to 44px.
- **Modal:** reuse existing Modal padding (`px-4 sm:px-6`, `py-4 sm:py-5`). Do not invent a new padding scale.

## Typography

Exactly four sizes and two weights for **new and touched** auth UI. Existing PageHeader (`text-xl`/`text-2xl` `font-bold`) and KPI (`text-2xl`/`text-3xl` `font-bold`) stay frozen — do not restyle them and do not reuse those sizes in the account menu or password modal.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | 600 | 1.5 |
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Heading | 16px (`text-base`) | 600 | 1.2 |
| Display | 18px (`text-lg`) | 600 | 1.2 |

- **Label (12/600/1.5):** Input labels, LoginScreen “Acesso ao Painel” (`uppercase tracking-wider`), error-banner text, account-menu items, Header nav (frozen).
- **Body (14/400/1.5):** Input values, Modal description, helper text. LoginScreen fields already `text-sm`.
- **Heading (16/600/1.2):** Modal title “Alterar senha” (Modal default `text-base font-semibold`).
- **Display (18/600/1.2):** LoginScreen brand “PlateFlow” (`text-lg font-semibold`) — keep; do not bump to 20/24.

Weights allowed in new UI: **400 and 600 only**. Do not add 500/700 on the account menu or password form. Existing Header brand `font-bold` (700) is frozen.

## Screens and interaction (this phase)

### 1. LoginScreen (AUTH-01) — keep layout

- Full-viewport dominant canvas, centered `max-w-sm` Card, QrCode 40×40 mark, Display title **PlateFlow**, Label header **Acesso ao Painel**.
- Submit uses `Button isLoading`; disable double submit.
- Success: parent `setUser` + load console (cookies set by API; **JS must not read or render the session cookie** — D-01).
- Login JSON has `{ user }` only — never show a token string in the UI.

### 2. Auth gate (AUTH-01 / ANLY-04)

- `isCheckingAuth`: existing centered `Loader2` on zinc-950. Do not paint Header, inventory, or cached plates until `/me` succeeds.
- `!user`: **only** LoginScreen. Header “Entrar” outline control is unreachable while the gate is on (App already skips Header). Do not restore a session from `AUTH_USER` localStorage when `/me` returns 401 (Pitfall 6 / CONTEXT discretion).
- GET 401 on plates/analytics/templates: `logout()` and LoginScreen; **never** substitute `localStorage` inventory/analytics into the lists.

### 3. Header account menu (AUTH-03) — new, thinnest chrome

- Entry is the **existing user chip** in `Header.tsx` (email prefix + logout). Do not add a settings route or a second top-level Header button.
- Chip is a `button` with `aria-haspopup="menu"` and `aria-expanded`. Panel: `absolute right-0 mt-2`, `z-50`, `min-w-[180px]`, secondary surface, `border-zinc-700`, `rounded-lg`, `py-1`.
- Menu items (Label 12/600): **Alterar senha** (opens Modal; `Lock` 14px icon `text-zinc-400`); **Sair** (existing `onLogout`, `LogOut` icon, `hover:text-rose-400`).
- Email prefix stays `hidden md:inline`, `font-mono`, `max-w-[100px] truncate` (overflow).
- Click-outside and Escape close the menu. Opening the password modal closes the menu.

### 4. Alterar senha Modal (AUTH-03)

- `Modal size="sm"`; fields stacked `space-y-4` like LoginScreen.
- `autocomplete="current-password"` on senha atual; `autocomplete="new-password"` on nova and confirmar.
- Client mismatch: set Input `error` on confirmar (and optionally nova) with the copy above; do not POST.
- Submit: primary **Alterar senha** `isLoading`; on 200 close modal, Toast **Senha alterada.**, operator **stays in the console** (new cookie pair — D-06). Do not force LoginScreen on success.
- On 401 during change-password: LoginScreen (session already dead).

### 5. Readings (ANLY-04) — existing table, lock columns

- Columns remain **Placa**, **Dispositivo**, **Data e Horário** only.
- Never render `log.ip`, never add an IP header, never title-tooltip an IP. Device Badge stays iOS/Android/neutral.
- Empty: existing EmptyState copy (table above).

### 6. Print lot (SHOP-01 + D-07) — do not rebuild

- `BatchGeneratorModal` / `imageComposerService` visuals and copy stay as-is.
- If access expires during ZIP: keep the modal mounted and `isProcessing` UI until the blob download starts; **then** send the operator to LoginScreen. Never swap to LoginScreen while the progress bar is visible.
